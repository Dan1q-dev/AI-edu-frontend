# Оформление Adaptive Learning

Визуальный образец: `https://test.aiedu.com.kz/`. Изменения предназначены для frontend основной платформы `https://aiedu.com.kz/` и сделаны поверх актуального `main`, а не через возврат старой версии приложения.

## Что перенесено

- Страница входа: синяя левая часть, геометрический фон, фирменный знак, заголовок AI Edu, переключатели входа и регистрации и языковые кнопки.
- Блок с формулой интегральной готовности и демонстрационные входы не отображаются.
- Общие цвета, фон, поверхности, кнопки, акценты и оглавление лекций собраны в `src/atlas-theme.css`. Новая навигация остаётся на прежнем месте. Мобильная навигация размещается в отдельной строке, чтобы все пункты оставались видимыми.

## Что сохранено

Маршруты, пользовательские роли, сессионная авторизация, CSRF, регистрация с выбором траектории и очистка состояния при смене аккаунта работают как в новой версии. API и backend не менялись. Каталог, курсы, практики, тесты, тьютор, редактор лекций, импорт материалов и управление пользователями не заменяются компонентами старого прототипа. Их расположение и логика сохраняются.

Переключатель языка использует существующий I18nProvider и хранилище locale. Новые надписи переведены на русский, казахский и английский. Цвета авторского текста внутри лекций не переписываются.

## Проверка

```bash
npm ci
npm test -- --maxWorkers=2
npm run build
```

Локально проходят 145 тестов и production-сборка. Выполнены браузерные проверки входа студента и администратора, выхода, каталога, курса, лекции, мобильной панели тьютора, конструктора, списка пользователей и редактора на desktop и mobile. Для просмотра использовалась отдельная локальная база с синтетическими материалами. Горизонтального переполнения на проверенных мобильных страницах нет; шапка лекции не перекрывает названия кнопками.

Фактическая генерация ИИ, распознавание речи и GPU-процессы в этой проверке оформления не запускались. Их код и контракты не менялись. Рабочие данные и сервер при локальной проверке не изменяются.

Для публикации достаточно стандартной сборки frontend, новых переменных окружения, миграций или переноса backend старого сайта не требуется. После принятия PR используется существующий процесс деплоя. До объединения и успешного деплоя основной сайт остаётся без изменений.
