# Мастерская генерации лекции

## Общая основа и конструкторы №2–3

`src/workspace/WorkshopChat.tsx` — общий чат для мастерской лекций и двух конструкторов.
`workshops.ts` задаёт тексты, тип документа и начальные элементы выбора, `types.ts` — контракты разделов.
История, очередь AI, повтор запросов с тем же UUID, Word-вложения, восстановление и самопроверка
реализованы один раз. `LectureWorkshop.tsx` сохраняет совместимый экспорт для существующих интеграций.

В каталоге практик доступны:

- №2 `practical_workshop` — тема, текст лекции в запросе или своя ранее созданная лекция; цель, задачи, результаты,
  задания базового, среднего и продвинутого уровней, кейсы, проблемные вопросы, этапы и оценивание.
- №3 `pedagogical_workshop` — семинар, круглый стол, дискуссия, деловая игра, кейс,
  исследовательское занятие, проектная работа или групповое занятие; полный сценарий выбранного формата.

Сначала пользователь пишет запрос. Если текст лекции уже есть в запросе или диалоге, помощник использует
его напрямую. При отсутствии текста помощник может предложить вставить текст, выбрать сохранённую лекцию
или продолжить по теме. Выбор появляется только у последнего ответа с `offer_source_lecture: true`;
до такого предложения список лекций не загружается. Предложение восстанавливается из истории после перезагрузки.

Исходные лекции загружаются через `GET workspace/source-lectures/` с пагинацией. При выборе лекции
в следующий запрос операции передаётся необязательный `source_lecture_id`; полный материал
добавляется к AI-контексту сервером. На следующих шагах сервер сохраняет исходную версию лекции.
Новые инструменты используют общую настройку задания; инструкция и критерии сохраняются при переключении.
Для включения обновите frontend, backend и workspace worker; дополнительных миграций нет.
Проверка экранов: `npx playwright test e2e/constructors.e2e.ts e2e/lecture-chat.e2e.ts`.

Практика открывается по `/items/:id` со страницы задания: название, описание, инструкция и критерии
самопроверки. Администратор выбирает инструмент — мастерскую лекций или практическое задание с отчётом.
Общие поля сохраняются при переключении инструмента. Конфигурация содержит `instructions`, `criteria`
и необязательный `source_url`; опубликованные исторические версии не изменяются.

Кнопка «Начать выполнение» создаёт попытку и открывает инструмент, «Продолжить выполнение» возвращает
в существующую попытку. Чат не открывается и AI не вызывается при просмотре страницы задания.

Студент пишет запрос и отправляет его кнопкой или Enter; Shift + Enter добавляет строку.
При открытии мастерской сервер открывает документ существующей попытки. Отдельные поля
названия лекции, темы, аудитории и других параметров отсутствуют. Ответ с полной лекцией появляется
в истории чата; последующие запросы уточняют предыдущий материал с учётом истории и текущей лекции.

Помощник уточняет тему, аудиторию, длительность и язык в чате. Вопрос содержит варианты ответа;
пользователь также может написать свой вариант. Обычно задаются 1–2 вопроса, максимум 3.
Всегда готовится полная лекция. После неё можно изменить раздел, добавить примеры или вопросы,
сократить текст либо попросить Word-файл. Действия предлагаются в последнем сообщении ассистента.
Постоянной кнопки экспорта нет: готовый DOCX появляется как вложение в ответе.
Поддерживается только DOCX; другие форматы файлов помощник не создаёт.

Мастерская занимает всю доступную область под навигацией курса без отдельной рамки и фиксированной
маленькой карточки. Компактная шапка и поле ввода остаются на месте; между ними прокручивается история.
Ввод начинается с одной строки, автоматически растёт до 160 px (не более 30% высоты экрана),
затем прокручивается внутри. После отправки или сокращения текста поле снова уменьшается.
На широком экране границу тьютора можно перетаскивать: ширина 260–560 px, с сохранением места
для основного чата. Ширина запоминается в браузере. Двойной щелчок возвращает 300 px;
при фокусе на границе доступны стрелки влево/вправо и Home/End. На мобильном тьютор открывается отдельно.

Кнопка «Самопроверка» открывает отдельный экран результата и критериев. Здесь можно скачать готовый
DOCX, вернуться к редактированию или инструкции. Кнопка «Завершить работу» доступна после подтверждения
обязательных критериев; сервер также проверяет их, наличие полной лекции и отсутствие текущей AI-операции.
Результат получает источник `SELF_ASSESSMENT`; самооценка не является оценкой преподавателя или AI.
В обычном практическом задании перед самопроверкой студент пишет отчёт и при необходимости указывает
HTTPS-ссылку на результат. Просмотр задания и переходы между экранами не засчитывают завершение.

Старые задания `checklist_practice` используют тот же общий сценарий с мастерской.
Сохраняется совместимость backend со старыми версиями без инструкции и критериев.

## API

Все пути относительны `/api/v1/`:

| Запрос | Данные |
| --- | --- |
| `GET items/{short_id}/practice/` | Версия, попытка, прогресс, `submission.document_id` |
| `POST items/{short_id}/practice/workspace/` | `{language: "ru" | "kk" | "en"}` |
| `GET workspace/documents/{id}/` | Сохранённая лекция и ревизия |
| `GET workspace/documents/{id}/messages/` | Все страницы истории; `content` ответа содержит лекцию |
| `POST workspace/documents/{id}/operations/` | `{request_id, revision, kind: "chat", prompt}` |
| `GET workspace/operations/{id}/` | Опрос статуса каждые 2 секунды до завершения |
| `GET workspace/artifacts/{id}/download/` | Скачивание DOCX по ссылке вложения |
| `POST items/{short_id}/practice/start/` | Начать или продолжить попытку |
| `POST items/{short_id}/practice/` | `{submission_id, submission_data: {completed: true, checks: [true], document_id, document_revision}}` |

При перезагрузке сначала отображается страница задания, без новой генерации. Документ находится через серверную
попытку, включая вход с другого устройства. В localStorage хранятся только идентификаторы,
раздельно для пользователя и попытки. Черновик отчёта, отметки критериев и данные экрана самопроверки
сохраняются в sessionStorage для этой вкладки. Неопределённый результат отправки повторяется с тем же UUID
и телом запроса. При отзыве доступа содержимое скрывается. Секреты AI остаются на backend.

Для генерации нужны настроенный AI API и работающий workspace worker; см. backend `docs/workspace.md`.
Сервер допускает до 10 активных запросов на пользователя в разных диалогах; внутри одного диалога
запросы выполняются последовательно. За час: 5 генераций, 10 редактирований и 10 DOCX.
Повторное скачивание готового файла бесплатно. Лекция — до 3000 слов, запрос — до 8000 символов.
Для нового диалога и вложений нужна backend-миграция `activities/0007_lecture_chat_and_artifacts.py`.
Миграция `activities/0005_alter_practiceresult_grading_source_and_more.py` добавляет источник `COMPLETION`.

Проверки: `npm run lint`, `npm test`, `npm run build`. Тесты чата используют mock API и проверяют
отправку без параметров, полный ответ, восстановление без localStorage, блокировку завершения при
генерации, повтор UUID, завершение, ошибки доступа и языки EN/KZ. Тесты `LectureEditor` сохранены
для существующего структурированного редактора, который больше не входит в интерфейс практики.
