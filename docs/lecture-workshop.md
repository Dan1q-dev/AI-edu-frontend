# Виртуальная работа №1 — frontend

Мастерская открывается по существующему `/items/:id`, когда закреплённая версия практики имеет
тип `lecture_workshop@1.0.0`. В административном редакторе тип использует прежний редактор критериев
самопроверки. Авторизация, доступ к материалам, начало попытки и сдача остаются в Practice Engine.
Backend должен иметь миграцию workspace, настроенный AI API и запущенный PostgreSQL worker;
инструкции находятся в backend `docs/workspace.md`.

## Пользовательский сценарий

1. Начать практическую работу.
2. Заполнить дисциплину, тему, курс обучения, аудиторию, продолжительность, сложность, результаты
   обучения и язык, затем нажать «Открыть документ». Это сохраняет параметры или возвращает имеющийся
   документ активной попытки. Казахский язык интерфейса `kz` соответствует языку лекции `kk`.
3. Ввести запрос. «Улучшить запрос» запускает только `improve_prompt`; результат появляется в поле
   ввода и доступен для ручного редактирования. Генерация после улучшения сама не запускается.
4. Нажать «Сгенерировать лекцию». При наличии лекции интерфейс просит подтвердить её замену.
   Статус операции опрашивается каждые 2 секунды до `SUCCEEDED/FAILED`. Ошибку можно повторить вручную.
5. Изменить название и содержимое разделов через существующий Tiptap. Навигация по разделам,
   предыдущий/следующий раздел и просмотр всей лекции сохраняют стабильные ID. На мобильном экране
   панели расположены вертикально, выбор раздела доступен через select. Оглавление курса открывается
   из верхней панели на любых размерах экрана.
6. Сохранить изменения вручную. Кнопки AI и сдачи недоступны при несохранённых изменениях,
   неизвестном статусе операции или конфликте ревизий. Во время AI-операции редактирование отключено.
7. Заполнить критерии самооценки и сдать практику. Сданный документ открывается для чтения;
   новая попытка начинает отдельную работу.

Параметры и документ сохраняются совместно. Редактор позволяет только поддерживаемое backend
форматирование; в режиме лекции отключены неподдерживаемые underline/strike/horizontalRule и вставка
изображений. HTML не рендерится. Исходная лекция имеет десять разделов с ID из backend-схемы;
неизвестный тип/версия схемы не открывается для редактирования.

## API и безопасность повторов

Используются только существующие endpoints, общий `api()`/`apiAll()` (сессия, CSRF, ошибки) и React Query:

| Запрос | Данные |
| --- | --- |
| `POST items/{short_id}/practice/workspace/` | `{parameters}` |
| `GET workspace/documents/{id}/` | Документ |
| `PATCH workspace/documents/{id}/` | `{revision, parameters, content?}`; пустой `content={}` не отправляется |
| `GET workspace/documents/{id}/messages/` | История с пагинацией; загружаются все страницы |
| `POST workspace/documents/{id}/operations/` | `{request_id, revision, kind, prompt}` |
| `GET workspace/operations/{id}/` | Состояние и результат |
| `POST items/{short_id}/practice/` | `{submission_id, submission_data:{document_id, document_revision, checks}}` |

Обновление страницы выполняет GET-запросы, не запускает генерацию. В localStorage сохраняются только
ID документа и последней операции, отдельно для пользователя и попытки. Сервер повторно проверяет
доступ, frontend проверяет связь документа с текущей попыткой и операции с документом. Данные
лекции, запросы, ключи AI и пользовательские ответы в localStorage не сохраняются.

Последнюю операцию также можно обнаружить по ID операции в истории сообщений. Если ответ на POST
потерян, ручной повтор использует тот же UUID и точное тело, исключая создание второй операции.
После явной ошибки завершённой операции новый запрос создаётся только по нажатию пользователя.

При `409` локальное содержимое остаётся в редакторе. Можно посмотреть версию с сервера и явно
загрузить её после подтверждения замены локальных изменений. Принудительной перезаписи чужой ревизии
нет. Перезагрузка/уход при несохранённых правках вызывает существующее предупреждение проекта.

## Ограничение текущего backend API

API не предоставляет GET поиска документа по попытке и список активных операций. Поэтому на другом
устройстве или после очистки localStorage активный документ нельзя автоматически найти. Пользователь
вводит действительные параметры и нажимает «Открыть документ»: существующий POST возвращает уже
сохранённый документ без перезаписи параметров. Сданный документ восстанавливается по `document_id`
из серверного снимка попытки. Новые API-поля или обходные endpoints не используются.

История сообщений пока не служит многоходовым контекстом AI. Редактирование отдельных разделов с
помощью AI, RAG и другие виртуальные работы не реализованы.

## Проверки и локальный запуск

Укажите локальный backend в `API_PROXY_TARGET` согласно существующей настройке проекта и запустите
`npm run dev`. Секреты AI находятся только в окружении backend. Не используйте рабочий backend для
проверок с тестовыми генерациями.

```bash
npm run lint
npm test
npm run build
```

Workspace-тесты используют mock API и проверяют создание/повторное открытие, сохранение JSON,
стабильность ID, конфликты, улучшение запроса, polling без повторного POST, повтор с тем же UUID,
сдачу, режим чтения, ошибки доступа и локализацию EN/KZ. Отдельный тест открывает настоящее содержимое
в Tiptap и проверяет выдачу структуры списка. Существующие тесты checklist practice выполняются вместе
с новой мастерской. Браузерную визуальную проверку следует выполнить локально перед публикацией.
